# 第一候选 v2：全曲理解 + 更干净的时间头（2026-10-23 收敛稿）

状态：**设计收敛，待独立审查后实现。** 基于 `design/FIRST_CANDIDATE.md`（v1）、`reports/training_framework_review_2026-10-23.md`、`reports/transcript_arch_review_2026-10-23.md` 与当天全部实测。v1 中未在此修改的部分继续有效。

## 0. 结论

1. **不重写主干**：冻结多层全频段音频记忆 + 事件 Transformer 联合注意力 + 时间指针，保留。
2. **新增一条可学习的"全曲理解流"**（三层：块内编码器 → 歌曲级 Transformer → 因果谱面流），**取代** v1 的 2 秒均值摘要 G 行。结构、重复、强弱、风格一致性由注意力学出，不引入检索/复制等启发式。
3. **时间头 v2**：40 ms 格指针 + 从该格冻结 token 读出的格内毫秒偏移（离散 logistic），onset 与长条尾部共用；指针加"最近 K 个起音的相对间隔核"作为节奏网格先验。**10 ms mel 支路的去留由相位探针决定**。
4. 训练与推理系统沿用当天已验证的实现：分桶 CUDA graph、有效组压缩、显卡常驻歌曲池、增量解码。
5. 验收是**双重帕累托**：谱面质量不退（整曲评测各项）、端到端时间与总费用不增、至少一项改善。

## 1. 目标与验收

- 能力目标：更快、更高效、更强，更好的谱面制作协助（从零、补全、锚点、参考风格、控制量）。
- 质量指标（整曲连续生成，前文只含已知事件与模型自身输出）：完成率、独立合法性、onset F1（10/20/50 ms）、音符 F1（类型 + 时间 + mania 键道）、长条头尾联合 F1 与尾部误差、**密度曲线相关性**（每 2 s 音符数曲线与真值的相关系数）、**重复一致性**（人谱中音频相似的段对上，生成谱段间相似度与人谱段间相似度之比）、**控制量响应**（`model/control_eval.py`：请求–达成 Spearman ≥ 0.5 且在带率 ≥ 0.3 才算可用）。按模式分别报。
- 效率指标：训练每有效样本的时间与费用（含数据等待、启动、验证）；推理每首歌的生成时间。
- 泄漏规则（唯一一条）：**标签**（当前及未来片段的音符和由其推导的量）不得进入任何输入或掩码；**音频随便看**，看多远只是算力取舍。

## 3. 架构 v2

### 3.1 冻结音频记忆（不变）
PupuM2D Large，tap {9,16,24}，40 ms 格 × 8 频段 × 1024 维，全维度 int8 缓存（`v4_i8_L9-16-24`）。每核心 16 s 局部窗口（400 格）。

### 3.2 全曲理解流（新）
| 层 | 输入 | 结构 | 输出 |
|---|---|---|---|
| **块内编码器** | 每 1 s 块：25 格 × 8 频段 × 3 tap 的冻结 token（先经与核心相同的 LayerNorm + 频段嵌入 + 学习的 tap 混合） | 2 层 d=256 注意力（块内相对位置）+ **注意力池化**（4 个可学习 query） | 每块 1 个 d=512 音频块 token（4 个池化向量拼接后投影） |
| **谱面块流** | 每 1 s 块内的已知事件：人给的 O + 当前核心起点之前已生成的事件；类型、键道/类型、块内相对时间、时长 | 小集合编码器（事件嵌入 + 注意力池化，2 个 query）；**起点之后的块一律"未知"占位 token** | 每块 1 个 d=512 谱面块 token |
| **歌曲级 Transformer** | 音频块 token + 谱面块 token（相加）+ 全曲相对时间 RoPE | 4 层 d=512、8 头、双向；长歌按块数截断到 1200 块（20 min） | 歌曲 token 序列 `S`，取代 v1 的 G 行进入核心联合注意力 |
- 自监督辅助目标：训练时随机遮 15% 音频块 token，由歌曲级输出预测被遮块的冻结特征均值（回归）。不需要标签；可单独在缓存上预训练（约 $0.5）作为 S1 初始化。
- 块宽 1 s 为默认；若旋律走向在小对照中不足，降到 250 ms（4 分钟歌约 960 token）。
- 代价估算：每批 2–4 首歌各编码一次；4 分钟歌 240 块 × 4 层 d=512 ≈ 0.2 GFLOP/首，相当于核心侧的 1/50。推理：每首歌音频流算一次缓存；谱面流每生成完一个核心更新一次。

### 3.3 核心事件模型
- 行集合：R（参考）/ I（意图）/ U（控制）/ **S（歌曲 token，替代 G）**/ K（已知）/ Y（生成）；可见性规则与 v1 相同（S 行对 Y 全开，无窗口）。
- 联合 softmax、GQA、1D 时间 RoPE、K/Y 的音频时间窗，不变。
- **时间头 v2**：
  1. 指针在 200 个 40 ms 格 + END + COPY_TIME 上选格（格 key 来自局部音频 token，沿用）；
  2. 选定格后，用该格 8 频段 × 3 tap 的 token 与行 query 产生**格内偏移**的离散 logistic 混合分布（1 ms 分辨率，允许越过格边界 ±10 ms）；
  3. 指针 logit 加**相对间隔核**：对最近 K=4 个起音，候选时刻与它们的间隔经可学习核（含整数倍/分数倍结构）得到偏置；不使用 BPM。
  4. 长条尾部：块 → 格 → 同一个格内偏移头（共用参数）。
  - 10 ms mel 支路：**相位探针**（在含 onset 的格上比较"冻结 token → 格内偏移"与"mel 卷积 → 格内偏移"的毫秒误差分布，噪声底线取 osu |r| 中位数 4 ms）成立则删除，否则保留并记录。
- 内层组解码：保留 GRU（已有效组压缩）；"一次联合预测 80 类和弦形状"列为后续可选项，不在 v2 范围。
- 取舍机制（I 行、选择场、L_cf）：保留，由 S1 配对训练 + 整曲评测裁决；评审指出的三处结构弱点记录在 §7。
- 暴露偏差：训练时对已生成上下文行（K 行中来自前文的部分、谱面块流中的已生成事件）施加扰动（10% 行丢弃、±10 ms 时间抖动），与全曲流一起启用。

### 3.4 推理
- 增量解码（每组只算新的一行，已验证等价）。
- 歌曲音频流按歌缓存；谱面流每核心更新；多首歌可批量。
- 内层采样向量化到设备（后续工程项）。

## 4. 训练系统（沿用，当天已验证或审阅）
分桶 CUDA graph（`TieredStep`，补齐只加被屏蔽的行，超大批次即时执行，最多录 2 个层级）；有效组压缩；元数据 worker + 显卡常驻歌曲池（容量 = worker × 模式 × 常驻数 + 预取）；CPU 预处理（验证片段、配对审计）；缓存索引文件；占用率守卫；非录制反向固定侧流。

## 7. 风险与未决
- 歌曲流只通过各核心的局部损失拿梯度，长程信号弱 → 遮块自监督目标兜底。
- 记忆越长暴露偏差越重 → 上下文扰动必须同时启用；整曲评测看完成率与误差积累。
- 取舍机制的结构弱点（参考音频频段被固定 query 池化；选择场是 8 个与音频无关标量的加权；配对少）：S1 若无效，按评审建议改成上下文内分类器（闭式岭回归），另立实验。
- S2 仍是旧数据路径：窗口去重按歌曲、冻结 1–20 层缓存第 20 层窗口状态，未实现。
- 40 ms 格对理解够用，对定位靠格内偏移头；一格内两个起音由两行 Y 各自的偏移分布表示。
- 显存：歌曲流按歌编码的激活很小；核心侧不变。
